A schema-driven generic form built on react-hook-form and Zod.

`GenericForm` takes a Zod schema, derives `initialValues` and validation from
it, and shares the form instance through `FormProvider` so any child can query
context with `useFormContext()`. Field components like `TextField` read the
context and render the state without wiring a `Controller` by hand. `DatePicker`
is the one exception: it is bound through a react-hook-form `Controller` (see
below).

## Usage

```tsx
import { GenericForm, TextField } from "@/components/edust-kit/generic-form"
import { z } from "zod"

const schema = z.object({
  name: z.string().min(1, "Name is required"),
  email: z.string().email("Invalid email"),
})

<GenericForm
  schema={schema}
  initialValues={{ name: "", email: "" }}
  onSubmit={(values) => console.log(values)}
>
  <TextField name="name" label="Name" required placeholder="John Doe" />
  <TextField name="email" label="Email" type="email" />
  <button type="submit">Submit</button>
</GenericForm>
```

## Imperative API

`GenericForm` forwards a ref exposing the full control surface:

| Ref property | Type                                  | Description                   |
| ------------ | ------------------------------------- | ----------------------------- |
| `getValues`  | `() => TValues`                       | Current form values.          |
| `reset`      | `(values?: Partial<TValues>) => void` | Reset the form.               |
| `setValue`   | `(name, value) => void`               | Set a single field.           |
| `formState`  | `FormState<TValues>`                  | State (errors, dirty, etc.).  |
| `control`    | `Control<TValues>`                    | RHF control for `Controller`. |
| `form`       | `UseFormReturn<TValues>`              | The full `useForm` return.    |

```tsx
const formRef = useRef<GenericFormRef<FormValues>>(null)

<GenericForm ref={formRef} ...>...</GenericForm>

formRef.current?.getValues()
formRef.current?.setValue("email", "a@b.com")
formRef.current?.reset()
```

## TextField

`TextField` is a single-line input bound to a schema field via react-hook-form
`Controller`. It renders a label, required marker, the `Input`, and the
resolved error message.

For `type="number"`, values are coerced to a number (or `null` when empty)
before being written to the form, so `onChange` payloads stay in sync with
zod+API shapes. Use `onValueChange` for custom coercion.

| Prop            | Type                                                            | Default  | Description                                         |
| --------------- | --------------------------------------------------------------- | -------- | --------------------------------------------------- |
| `name`          | `Path<TValues>`                                                 | —        | Field name (must exist in the schema).              |
| `label`         | `string`                                                        | —        | Label text; hidden when empty.                      |
| `type`          | `"text" \| "email" \| "number" \| "password" \| "tel" \| "url"` | `"text"` | Input type.                                         |
| `placeholder`   | `string`                                                        | —        | Input placeholder.                                  |
| `required`      | `boolean`                                                       | `false`  | Renders the red `*` marker.                         |
| `disabled`      | `boolean`                                                       | `false`  | Disables the input.                                 |
| `className`     | `string`                                                        | —        | Classes for the field wrapper.                      |
| `inputClass`    | `string`                                                        | —        | Classes for the input.                              |
| `min` / `max`   | `number \| string`                                              | —        | Min/max bounds (numbers).                           |
| `step`          | `number \| string`                                              | —        | Step for number inputs.                             |
| `autoComplete`  | `string`                                                        | —        | Browser autofill hint.                              |
| `onValueChange` | `(value: string \| number \| null) => void`                     | —        | Custom value transform; bypasses built-in coercion. |

## SelectField

`SelectField` is a single select bound to a schema field via react-hook-form
`Controller`. It renders a label, required marker, a `Select` trigger, the
option list, and the resolved error message.

```tsx
import { SelectField } from "@/components/edust-kit/generic-form/select-field"
import { z } from "zod"

enum StatementType {
  Income = "Income",
  Expense = "Expense",
  Transfer = "Transfer",
}

const schema = z.object({
  statementType: z.enum(["Income", "Expense", "Transfer"]),
})

;<GenericForm schema={schema} initialValues={{ statementType: "" }} onSubmit={...}>
  <SelectField
    name="statementType"
    label="Statement Type"
    required
    placeholder="Select statement type"
    options={Object.values(StatementType)}
  />
</GenericForm>
```

`options` accepts any of three shapes, all copy-paste ready. Pick whichever
matches your data.

**1. Array of strings** — value and label are the same string:

```tsx
import { SelectField } from "@/components/edust-kit/generic-form/select-field"
import { z } from "zod"

const schema = z.object({
  statementType: z.enum(["Income", "Expense", "Transfer"]),
})

;<GenericForm schema={schema} initialValues={{ statementType: "" }} onSubmit={...}>
  <SelectField
    name="statementType"
    label="Statement Type"
    required
    placeholder="Select statement type"
    options={["Income", "Expense", "Transfer"]}
  />
</GenericForm>
```

Works with `Object.values(...)` of a TS enum too:

```tsx
enum StatementType {
  Income = "Income",
  Expense = "Expense",
  Transfer = "Transfer",
}

;<SelectField
  name="statementType"
  label="Statement Type"
  required
  placeholder="Select statement type"
  options={Object.values(StatementType)}
/>
```

**2. Array of `{ value, label }`** — value stays stable while the label is
whatever you display:

```tsx
const schema = z.object({
  country: z.string(),
})

;<GenericForm schema={schema} initialValues={{ country: "" }} onSubmit={...}>
  <SelectField
    name="country"
    label="Country"
    required
    placeholder="Pick a country"
    options={[
      { value: "ID", label: "Indonesia" },
      { value: "US", label: "United States" },
      { value: "GB", label: "United Kingdom" },
      { value: "JP", label: "Japan" },
    ]}
  />
</GenericForm>
```

**3. `Record<string, string>` map** — API keys as values, human labels as the
map values:

```tsx
const schema = z.object({
  status: z.enum(["draft", "published", "archived"]),
})

;<GenericForm schema={schema} initialValues={{ status: "" }} onSubmit={...}>
  <SelectField
    name="status"
    label="Status"
    required
    placeholder="Pick a status"
    options={{
      draft: "Draft",
      published: "Published",
      archived: "Archived",
    }}
  />
</GenericForm>
```

They also work together — e.g. an enum for the stored value, a custom label or
`emptyOption` (adds a "None" item that resets the field to `""`):

```tsx
;<SelectField
  name="status"
  label="Status"
  placeholder="Pick a status"
  options={Object.values(Status)}
  emptyOption={{ label: "None" }}
/>
```

| Prop            | Type                                                                  | Default       | Description                                      |
| --------------- | --------------------------------------------------------------------- | ------------- | ------------------------------------------------ |
| `name`          | `Path<TValues>`                                                       | —             | Field name (must exist in the schema).           |
| `label`         | `string`                                                              | —             | Label text; hidden when empty.                   |
| `placeholder`   | `string`                                                              | `"Select..."` | Select placeholder.                              |
| `description`   | `string`                                                              | —             | Helper text under the select.                    |
| `required`      | `boolean`                                                             | `false`       | Renders the red `*` marker.                      |
| `disabled`      | `boolean`                                                             | `false`       | Disables the select.                             |
| `className`     | `string`                                                              | —             | Classes for the field wrapper.                   |
| `triggerClass`  | `string`                                                              | —             | Classes for the trigger.                         |
| `options`       | `ReadonlyArray<string \| { value, label }> \| Record<string, string>` | —             | The selectable options.                          |
| `emptyOption`   | `{ value?: string; label?: string }`                                  | —             | Adds a "None" item at the top that clears value. |
| `onValueChange` | `(value: string) => void`                                             | —             | Custom handler; overrides the default write.     |

For remotely fetched option lists, use [`AsyncSelectField`](#asyncselectfield)
instead.

## PhoneField

`PhoneField` is a phone number input bound to a schema field via
react-hook-form `Controller`. Built on `react-phone-number-input`, it renders a
country selector (with flags and search) plus the number input, and normalizes
empty input to an empty string.

The stored value is an **E.164 string** (e.g. `+628123456789`). Validate it with
a regex rule in your schema:

```tsx
import { PhoneField } from "@/components/edust-kit/generic-form/phone-field"

const schema = z.object({
  phone: z
    .string()
    .regex(/^\+?[1-9]\d{6,14}$/, "Invalid phone number"),
})

;<GenericForm schema={schema} initialValues={{ phone: "" }} onSubmit={...}>
  <PhoneField name="phone" label="Phone" required defaultCountry="ID" />
</GenericForm>
```

| Prop             | Type                                                        | Default | Description                                           |
| ---------------- | ----------------------------------------------------------- | ------- | ----------------------------------------------------- |
| `name`           | `Path<TValues>`                                             | —       | Field name (must exist in the schema).                |
| `label`          | `string`                                                    | —       | Label text; hidden when empty.                        |
| `placeholder`    | `string`                                                    | —       | Input placeholder.                                    |
| `description`    | `string`                                                    | —       | Helper text under the input.                          |
| `required`       | `boolean`                                                   | `false` | Renders the red `*` marker.                           |
| `disabled`       | `boolean`                                                   | `false` | Disables the field.                                   |
| `className`      | `string`                                                    | —       | Classes for the field wrapper.                        |
| `defaultCountry` | `React.ComponentProps<typeof PhoneInput>["defaultCountry"]` | `"BD"`  | Default country code (ISO 3166-1 alpha-2, uppercase). |

`PhoneField` also accepts the bare `PhoneInput` (no form binding) directly:

```tsx
import { PhoneInput } from "@/components/edust-kit/generic-form/phone-input"

;<PhoneInput
  value={phone}
  onChange={setPhone}
  defaultCountry="ID"
  placeholder="Enter phone number"
/>
```

## Validation

Validation is driven entirely by the Zod schema. A field that fails its schema
rule is marked invalid (`data-invalid`) and shows the error message from the
schema:

```tsx
const schema = z.object({
  email: z.string().email("Enter a valid email address"),
})
```

## Error handling

`TextField` renders `FieldError` automatically when the field is invalid. When
an arbitrary `FieldError` is needed outside a text field, the underlying
component reads `useFormContext().formState.errors` directly.

## AsyncMultiSelectField

A searchable multi-select for remotely fetched data. Built on `Popover` and
`Command` (cmdk), it fetches options from an API with debounced search, renders
selected values as removable badges, supports infinite scrolling for paginated
responses, and handles loading, error, and empty states.

```tsx
import { AsyncMultiSelectField } from "@/components/edust-kit/generic-form"

;<AsyncMultiSelectField
  value={selectedIds}
  onChange={setSelectedIds}
  useDataHook={useLabelsHook}
  getItemDisplayValue={(item) => item.name}
  placeholder="Select labels..."
/>
```

### Props

`AsyncMultiSelectField` is generic over `<T, TParams>` where `T` is the item
type and `TParams` is the params type passed to `useDataHook`.

| Prop                  | Type                                             | Default            | Description                                                                                |
| --------------------- | ------------------------------------------------ | ------------------ | ------------------------------------------------------------------------------------------ |
| `value`               | `string[]`                                       | `[]`               | Currently selected item IDs.                                                               |
| `onChange`            | `(values: string[]) => void`                     | —                  | Called with the full array whenever the selection changes.                                 |
| `placeholder`         | `string`                                         | `"Select..."`      | Text shown when nothing is selected.                                                       |
| `className`           | `string`                                         | —                  | Classes for the trigger button.                                                            |
| `badgeClassName`      | `string`                                         | —                  | Classes for the selected-value badges.                                                     |
| `debounceDelay`       | `number`                                         | `500`              | Debounce delay in ms for search input.                                                     |
| `searchPlaceholder`   | `string`                                         | `"Search..."`      | Placeholder for the search input.                                                          |
| `searchParamKey`      | `keyof TParams`                                  | `"search_by_name"` | The param key used for the search term.                                                    |
| `useDataHook`         | `(params: TParams) => AsyncSelectQueryResult<T>` | —                  | Hook that fetches items given params; may return `pagination` for infinite scrolling.      |
| `selectedItemsData`   | `AsyncSelectData<T>`                             | —                  | Pre-fetched data used to resolve badge labels for selected items outside the fetched page. |
| `getItemDisplayValue` | `(item: T) => string`                            | —                  | Returns the plain-text label (badges and dropdown fallback).                               |
| `renderItemLabel`     | `(item: T) => React.ReactNode`                   | —                  | Custom render for dropdown option content.                                                 |
| `getItemKey`          | `(item: T) => string`                            | `item.id`          | Unique React key for an item.                                                              |
| `getItemValue`        | `(item: T) => string`                            | `item.id`          | The value (ID) of an item.                                                                 |
| `additionalParams`    | `Partial<Omit<TParams, keyof BaseSelectParams>>` | `{}`               | Extra params merged into every request.                                                    |
| `disabled`            | `boolean`                                        | `false`            | Disables the field.                                                                        |
| `maxSelected`         | `number`                                         | —                  | Maximum number of selections allowed.                                                      |
| `maxBadges`           | `number`                                         | `4`                | How many selected badges to render before showing `+N`.                                    |
| `showSearchIcon`      | `boolean`                                        | `false`            | Show a search icon inside the search input.                                                |
| `lazy`                | `boolean`                                        | `false`            | Fetch the dropdown list only after the popover is opened.                                  |
| `emptyIndicator`      | `React.ReactNode`                                | —                  | Custom empty-state message.                                                                |

### With react-hook-form

```tsx
import { AsyncMultiSelectField } from "@/components/edust-kit/generic-form"
import { Controller, useForm } from "react-hook-form"

type FormValues = {
  labelIds: string[]
}

export function TaskForm() {
  const form = useForm<FormValues>({ defaultValues: { labelIds: [] } })

  return (
    <Controller
      name="labelIds"
      control={form.control}
      render={({ field }) => (
        <AsyncMultiSelectField
          value={field.value}
          onChange={field.onChange}
          useDataHook={useLabelsHook}
          getItemDisplayValue={(item) => item.name}
          placeholder="Select labels..."
        />
      )}
    />
  )
}
```

### Limiting selections

Pass `maxSelected` to cap the number of items the user can pick. When the cap is
reached the dropdown shows a hint and further selections are ignored.

```tsx
<AsyncMultiSelectField
  maxSelected={3}
  value={selectedIds}
  onChange={setSelectedIds}
  useDataHook={useLabelsHook}
  getItemDisplayValue={(item) => item.name}
/>
```

### Resolving badge labels

The trigger resolves badge labels from the fetched list plus
`selectedItemsData`. When a selected value does not appear in the current page
(e.g. paginated results), pass pre-fetched data so its badge still renders:

```tsx
const { data: selectedLabelsData } = useGetLabels(
  selectedIds.length ? { ids: selectedIds } : undefined,
)

<AsyncMultiSelectField
  value={selectedIds}
  onChange={setSelectedIds}
  useDataHook={useLabelsHook}
  selectedItemsData={selectedLabelsData}
  getItemDisplayValue={(item) => item.name}
/>
```

### Paginated loading

When the data hook returns the standard `pagination` metadata, the field sends
`page` in the request parameters, loads the next page when the list reaches the
bottom, and keeps already-loaded options visible while the next page is loading.
The response shape is the same as `AsyncSelectField`:

```tsx
type ItemsResponse = {
  data: { items: Item[] }
  pagination?: {
    hasNextPage?: boolean
    nextPage?: number | null
  }
}
```

Existing single-page hooks continue to work when `pagination` is omitted.

## AsyncSelectField

An async single-select field for remotely fetched data. Built on `Popover` and
`Command` (cmdk), fetches options from an API with debounced search, loading/
error states, infinite scrolling for paginated responses, and support for
pre-fetching the selected item's display value.

```tsx
import { AsyncSelectField } from "@/components/edust-kit/generic-form"

;<AsyncSelectField
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  getItemDisplayValue={(item) => item.name}
  placeholder="Select an item..."
/>
```

and `TParams` is the params type passed to `useDataHook`.

| `className`           | `string`                                         | —                  | Additional CSS classes for the trigger button.                                          |
| `debounceDelay`       | `number`                                         | `500`              | Debounce delay in ms for search input.                                                  |

| `getItemKey`          | `(item: T) => string`                            | `item.id`          | Returns a unique key for React rendering.                                               |

| `disabled`            | `boolean`                                        | `false`            | Disables the select field.                                                              |
| `showSearchIcon`      | `boolean`                                        | `false`            | Show a search icon inside the search input.                                             |

| `lazy`                | `boolean`                                        | `false`            | Fetch the dropdown list only after the popover is opened instead of on mount.           |

### With react-hook-form

```tsx
import { AsyncSelectField } from "@/components/edust-kit/generic-form"
import { Controller, useForm } from "react-hook-form"

type FormValues = {
  currencyId: string
}

export function CurrencyForm() {
  const form = useForm<FormValues>()

  return (
    <Controller
      name="currencyId"
      control={form.control}
      render={({ field }) => (
        <AsyncSelectField
          value={field.value}
          onChange={field.onChange}
          useDataHook={useCurrenciesHook}
          getItemDisplayValue={(item) => `${item.code} — ${item.name}`}
          placeholder="Select currency..."
        />
      )}
    />
  )
}
```

### Pre-fetching selected item

When the selected item may not be in the initial fetch (e.g. paginated results),
pass `selectedItemData` so the trigger button can display the correct label:

```tsx
const { data: selectedItemData } = useGetItem(selectedId ? { ids: [selectedId] } : undefined)

<AsyncSelectField
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  selectedItemData={selectedItemData}
  getItemDisplayValue={(item) => item.name}
/>
```

### Custom option labels

Use `renderItemLabel` to render arbitrary JSX in the dropdown (icons, multi-line,
badges, etc.). The trigger always uses `getItemDisplayValue` for plain text.

```tsx
<AsyncSelectField
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  getItemDisplayValue={(item) => item.code}
  renderItemLabel={(item) => (
    <div className="flex items-center gap-2">
      <span className="font-medium">{item.symbol}</span>
      <span>{item.code}</span>
      <span className="text-muted-foreground text-xs">{item.name}</span>
    </div>
  )}
/>
```

### Lazy loading

By default the dropdown list is fetched as soon as the component mounts. On
forms with many async selects (e.g. supplier, currency, product pickers on the
same page) this fires a burst of requests at once and can exceed API rate
limits. Pass `lazy` to defer fetching until the user opens the popover:

```tsx
<AsyncSelectField
  lazy
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  getItemDisplayValue={(item) => item.name}
/>
```

The selected item's label still renders immediately from `selectedItemData`
(no extra fetch is needed for the trigger while the popover is closed).

### Paginated loading

When the data hook returns the standard `pagination` metadata, the field sends
`page` in the request parameters, loads the next page when the list reaches the
bottom, and keeps already-loaded items visible while the next page is loading.
The hook should preserve the API response shape:

```tsx
type ItemsResponse = {
  data: { items: Item[] }
  pagination?: {
    hasNextPage?: boolean
    nextPage?: number | null
  }
}

const useItemsHook = (params: { page?: number; search_by_name?: string }) =>
  useQuery({
    queryKey: ["items", params],
    queryFn: () => getItems(params),
  })
```

No component-specific pagination code is required. Existing single-page hooks
continue to work when `pagination` is omitted.

### Custom empty state

Use `emptyIndicator` to replace the default empty text with custom content:

```tsx
<AsyncSelectField
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  getItemDisplayValue={(item) => item.name}
  emptyIndicator={
    <div className="text-muted-foreground py-6 text-center text-sm">
      No matching items
    </div>
  }
/>
```

### Custom styling

Pass `className` to customize the trigger button (height, width, font size,
etc.):

```tsx
<AsyncSelectField
  className="h-7 max-w-xs text-[0.8rem]"
  value={selectedId}
  onChange={setSelectedId}
  useDataHook={useItemsHook}
  getItemDisplayValue={(item) => item.name}
/>
```

## DatePicker

A calendar date picker bound through react-hook-form `Controller`. Wrap the
picker in a `Controller` to bind it to a form field. The picker writes a UTC ISO
string via `field.onChange`, combining the selected calendar day with the
current time at the moment of selection.

### Typing dates

The type-to-enter UX is opt-in via the `variant` prop. The default `"button"`
keeps the original label-style trigger that opens the calendar; pass
`variant="input"` to render a field where users can type a date directly
instead of clicking the calendar. Both variants open the same calendar popover.

Accepted typed formats (day/month/year, with or without leading zeros and
optional separators):

- `1482026` → 14 Aug 2026 (DDMMYYYY, unpadded month)
- `14082026` → 14 Aug 2026 (DDMMYYYY)
- `14/08/2026`, `14-8-2026` → 14 Aug 2026
- `2026-08-14` → 14 Aug 2026 (YYYY-MM-DD)
- `140825` → 14 Aug 2025 (DDMMYY)

The value is committed as soon as the input forms a valid date; invalid or
partial input is ignored until complete.

```tsx
<DatePicker
  field={field}
  fieldState={fieldState}
  label="Start date"
  variant="input"
/>
```

### Value shape

The stored value is always a full ISO 8601 UTC timestamp: the selected calendar
day with the **current local time of day** stamped on it, serialized in UTC.

**Format:** `YYYY-MM-DDTHH:mm:ss.sssZ`

```text
2026-08-14T07:23:41.123Z
└──┬───┘ └─┬─┘ └─┬─┘ └┬┘ └┬┘
  date   month  time  ms  Z = UTC
```

```json
{
  "startDate": "2026-08-14T07:23:41.123Z"
}
```

- The **date** is the day the user picked in the calendar or typed.
- The **time** is the current local time at the moment of selection (not
  midnight), so two picks on the same day still differ by their time.
- It is always `...Z` (UTC), regardless of the viewer's timezone.

If you only need the date and not the time, strip it after parsing, or use a
`z` transform in your schema (see below).

### Validation (Zod)

Validate the field with `z.iso.datetime` (Zod v4). Use `.optional()` when the
field is not required, and `.refine()` to enforce a minimum date.

```tsx
import { z } from "zod"

const formSchema = z.object({
  startDate: z.iso
    .datetime("Please select a valid date")
    .refine((value) => new Date(value) >= new Date("2026-01-01"), {
      message: "Date must be in 2026 or later",
    }),
  endDate: z.iso.datetime().optional(),
})
```

To read it back as a `Date` (e.g. for an API or another component):

```ts
const date: Date = new Date(form.getValues("startDate"))
// → Date object for 2026-08-14T07:23:41.123Z
```

### Basic usage

```tsx
import { DatePicker, GenericForm } from "@/components/edust-kit/generic-form"

type FormValues = {
  startDate: string
}

export function EventForm() {
  const form = useForm<FormValues>()

  return (
    <Controller
      name="startDate"
      control={form.control}
      render={({ field, fieldState }) => (
        <DatePicker
          field={field}
          fieldState={fieldState}
          label="Start date"
          required
        />
      )}
    />
  )
}
```

### Default value

The field expects a UTC ISO string, so seed it with `new Date().toISOString()`
to preselect the current date and time:

```tsx
const form = useForm<FormValues>({
  defaultValues: {
    startDate: new Date().toISOString(), // e.g. "2026-08-14T07:23:41.123Z"
  },
})
```

Any value parseable by `Date` (or a `Date` object) also works, since the picker
accepts both string and `Date` values.

### Constrained usage (min/max, disabled days, placeholder)

`startMonth` / `endMonth` bound the navigable range, `disabledDates` disables
specific days, and `placeholder` overrides the empty text.

```tsx
import { DatePicker } from "@/components/edust-kit/generic-form"
import { Controller, useForm } from "react-hook-form"

export function BookingForm() {
  const form = useForm<{ startDate: string }>()

  return (
    <Controller
      name="startDate"
      control={form.control}
      render={({ field, fieldState }) => (
        <DatePicker
          field={field}
          fieldState={fieldState}
          label="Booking date"
          required
          placeholder="Choose a booking date"
          startMonth={new Date(2026, 0, 1)}
          endMonth={new Date(2026, 11, 31)}
          disabledDates={(date) => date.getDay() === 0}
        />
      )}
    />
  )
}
```

### Props

`DatePicker` is generic over your form values and field name
(`<TFieldValues, TName>`). Beyond the `field` / `fieldState` from a
`Controller`, it accepts:

| Prop            | Type                                                             | Default         | Description                                                            |
| --------------- | ---------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------- |
| `label`         | `string`                                                         | —               | Field label (required).                                                |
| `variant`       | `"button" \| "input"`                                            | `"button"`      | `"button"` = label trigger; `"input"` = type-to-enter field.           |
| `required`      | `boolean`                                                        | `true`          | Shows a required marker and marks the trigger.                         |
| `disabled`      | `boolean`                                                        | `false`         | Disables the whole control.                                            |
| `placeholder`   | `string`                                                         | `"Pick a date"` | Empty-state text on the trigger.                                       |
| `startMonth`    | `Date`                                                           | —               | Earliest selectable month (inclusive). Also bounds the dropdown range. |
| `endMonth`      | `Date`                                                           | —               | Latest selectable month (inclusive). Also bounds the dropdown range.   |
| `disabledDates` | `Matcher \| Matcher[]` (react-day-picker)                        | —               | Disables specific days.                                                |
| `captionLayout` | `"label" \| "dropdown" \| "dropdown-months" \| "dropdown-years"` | `"dropdown"`    | Calendar caption layout.                                               |
| `locale`        | `Locale` (date-fns)                                              | —               | Locale for formatting and the calendar.                                |
| `displayFormat` | `string`                                                         | `"PPP"`         | date-fns format string for the trigger label.                          |

`captionLayout` defaults to `"dropdown"` — pass `"label"` to switch to a
simple label:

```tsx
<DatePicker
  field={field}
  fieldState={fieldState}
  label="Start date"
  captionLayout="label"
/>
```

### Dropdown navigation range

With `captionLayout="dropdown"`, the year/month dropdowns only span the range
set by `startMonth` / `endMonth`. If you omit them, the year dropdown defaults
to **[current year − 100, current year]** — so future years like 2030 will not
appear unless you extend `endMonth`. `startMonth` / `endMonth` also disable
dates outside that range.

```tsx
<DatePicker
  field={field}
  fieldState={fieldState}
  label="Event date"
  variant="input"
  captionLayout="dropdown"
  startMonth={new Date(2020, 0, 1)}
  endMonth={new Date(2030, 11, 31)}
/>
```
